# Plan: Tách pipeline Download/Transfer + Backpressure tmp space

## Mục tiêu
Khi `useTmp=true` và saveDir là HDD:
- Download về SSD tmp với `maxSsdTasks` concurrency (không phụ thuộc saveDir drive type)
- Sau khi download+verify xong, giải phóng scheduler slot và connections ngay
- Transfer (move tmp → final) chạy riêng với `maxTransfers` concurrency
- Thêm gate tmp space vào scheduler để tránh tmp đầy

## Luồng hiện tại vs mới

```
HIỆN TẠI:
task.run() = runDownload()
  → download to tmp
  → verify
  → executeMove() ← giữ scheduler slot + connections trong suốt transfer
  → completed → giải phóng slot

MỚI:
task.run() = runDownload()
  → download to tmp
  → verify
  → return ← giải phóng slot + connections NGAY
  → TransferQueue.enqueue() ← chạy riêng, không giữ scheduler slot
    → transfer complete → giải phóng tmp space → drain scheduler
```

### 3. `electron/modules/downloader/downloader.ts`

#### TransferQueue enhancements:
- Track `taskId` cho mỗi transfer entry
- Thêm `pauseTransfer(taskId)` → gọi `pauseNativeTransfer(rustId)`
- Thêm `resumeTransfer(taskId)` → gọi `resumeNativeTransfer(rustId)`
- Thêm `cancelTransfer(taskId)` → gọi `cancelNativeTransfer(rustId)`
- Map `taskId → rustTransferId` để track
- Emit `transfer_complete` và `transfer_cancelled` events

#### `add()` method:
- Khi `useTmp=true`, gọi `findTmpDir()` sớm để biết tmp drive
- Nếu có tmp drive, set `driveCategory = "internal_ssd"` (dù saveDir là HDD)
- Reserve tmp space ngay: `diskManager.reserveTmp(id, firmware.filesize, tmpDrivePath)`
- Pass `needsTmp: true` vào scheduler task

#### `runDownload()` method:
- Bỏ Step 8 (executeMove) khỏi runDownload
- Sau khi download+verify xong:
  - Nếu dùng tmp: enqueue vào TransferQueue, return ngay
  - Nếu không dùng tmp: mark completed như hiện tại
- Task status flow: downloading → verifying → (transferring nếu dùng tmp) → completed

#### `executeMove()` → giờ được gọi bởi TransferQueue callback:
- Vẫn giữ logic same-drive rename vs cross-drive transfer
- Khi xong: release tmp space, drain scheduler

#### `pause()` method:
- Nếu task đang "transferring": gọi `transferQueue.pauseTransfer(id)`
- Nếu task đang "downloading": gọi ChunkManager.abort() như hiện tại

#### `resume()` method:
- Nếu task đang paused và tmpPath exists: gọi `transferQueue.resumeTransfer(id)`

#### `cancel()` method:
- Nếu task đang "transferring": gọi `transferQueue.cancelTransfer(id)`, release tmp space
- Nếu task đang "downloading": abort ChunkManager như hiện tại

#### `setConfig()` / `updateConfig()`:
- Cập nhật TransferQueue.maxTransfers khi config thay đổi

## Backpressure flow

```
1. Task A, B, C đang download về tmp (maxSsdTasks=3)
2. Task A download xong → giải phóng slot → enqueue TransferQueue
3. Scheduler drain → kiểm tra tmp space cho Task D
   - Nếu tmp còn đủ chỗ → start Task D
   - Nếu tmp gần đầy → Task D chờ
4. TransferQueue hoàn thành Task A → release tmp space → emit event
5. Event trigger scheduler.drain() → Task D có thể start
```

## Edge cases cần xử lý

1. **Same-drive rename**: Nếu tmp và save cùng drive, rename là instant. Vẫn giải phóng scheduler slot trước khi rename (để consistency).

2. **No tmp (direct download)**: Không thay đổi behavior. Scheduler slot giải phóng khi download+verify xong.

3. **findTmpDir trả null khi drain**: Task fallback về direct download (như hiện tại). driveCategory vẫn là saveDir category.

4. **User pause khi đang transfer**: Gọi `pauseNativeTransfer` từ Rust. TransferQueue giữ state, resume sẽ gọi `resumeNativeTransfer`.

5. **Crash recovery**: State file có `activeOperation: "move"`. Recovery sẽ gọi `executeMove()` trực tiếp (không qua scheduler). Cần handle cả trường hợp tmp file đã bị xóa.

6. **Tmp space calculation**: Reserve full file size ngay khi enqueue (conservative). Actual disk usage có thể ít hơn (partial download), nhưng an toàn hơn.
