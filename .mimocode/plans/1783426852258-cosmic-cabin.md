# Fix: IOWriteQueue & MoveQueue I/O contention trên HDD

## Vấn đề

Trong môi trường `hdd_ssd_tmp`, khi turbo task (Task 1) hoàn tất download và đang drain IOWriteQueue (ghi chunks từ SSD tmp → `.turbo` trên HDD), nếu normal task (Task 2) cũng hoàn tất download và bắt đầu move qua MoveQueue (ghi SSD tmp → HDD), cả 2 cùng ghi vào HDD đồng thời gây I/O contention.

Nếu IOWriteQueue gặp lỗi do contention → `stopped=true` → Task 1 rơi vào fallback path dùng MoveQueue → phải chờ vì `hddLimit=1`.

## Nguyên nhân gốc

IOWriteQueue và MoveQueue không chia sẻ concurrency limit cho cùng 1 ổ đĩa. Mỗi cái quản lý concurrency độc lập:
- MoveQueue: `concurrency` map per drive key, `hddLimit=1`
- IOWriteQueue: `maxConcurrency=2`, hoàn toàn độc lập

## Giải pháp

Cho IOWriteQueue "tham gia" vào MoveQueue's concurrency tracking. Trước mỗi chunk move, IOWriteQueue kiểm tra xem MoveQueue có slot trống trên cùng ổ đĩa không. Nếu không → chờ.

## Files cần sửa

1. **`electron/modules/downloader/downloader.ts`** — MoveQueue class
2. **`electron/modules/downloader/chunk-manager.ts`** — IOWriteQueue + ChunkManagerOptions

## Chi tiết implement

### Bước 1: Thêm `acquireSlot` / `releaseSlot` vào MoveQueue (`downloader.ts`)

```typescript
// MoveQueue — thêm 2 methods mới:

/**
 * Acquire a write slot on the given drive. Waits until the current
 * concurrency for that drive is below `limit`, then increments it.
 * Used by IOWriteQueue to coordinate HDD writes.
 */
async acquireSlot(key: string, limit: number): Promise<void> {
  while ((this.concurrency.get(key) ?? 0) >= limit) {
    await new Promise(r => setTimeout(r, 100));
  }
  this.concurrency.set(key, (this.concurrency.get(key) ?? 0) + 1);
}

/** Release a previously acquired slot. */
releaseSlot(key: string): void {
  this.concurrency.set(key, Math.max(0, (this.concurrency.get(key) ?? 0) - 1));
}

/** Query whether any move is active on the given drive. */
getConcurrency(key: string): number {
  return this.concurrency.get(key) ?? 0;
}

getHddLimit(): number {
  return this.hddLimit;
}
```

### Bước 4: IOWriteQueue acquire/release slot (`chunk-manager.ts`)

Thêm params vào constructor:
```typescript
constructor(
  // ... existing params ...
  private moveQueue?: { acquireSlot(key: string, limit: number): Promise<void>; releaseSlot(key: string): void; getHddLimit(): number; },
  private driveKey?: string,
)
```

Trong `scheduleNext`, trước khi bắt đầu move chunk:
```typescript
private scheduleNext(): void {
  while (this.activeCount < this.maxConcurrency && this.queue.length > 0 && !this.stopped) {
    const chunk = this.queue.shift()!;
    this.activeCount++;
    this.moveChunkWithSlot(chunk)  // ← đổi từ moveChunk
      .catch((err: any) => {
        this.stopped = true;
        if (this.onError) this.onError(err);
      })
      .finally(() => {
        this.activeCount--;
        if (!this.stopped) this.scheduleNext();
        this.checkDrain();
      });
  }
}

private async moveChunkWithSlot(chunk: QueuedChunk): Promise<void> {
  // Acquire slot from MoveQueue if available (coordinate HDD writes)
  if (this.moveQueue && this.driveKey) {
    await this.moveQueue.acquireSlot(this.driveKey, this.moveQueue.getHddLimit());
  }
  try {
    await this.moveChunk(chunk);
  } finally {
    if (this.moveQueue && this.driveKey) {
      this.moveQueue.releaseSlot(this.driveKey);
    }
  }
}
```

### Bước 6: Cleanup khi stop/drain

Trong `IOWriteQueue.stop()`, đảm bảo release slot nếu có chunk đang in-flight:
```typescript
async stop(): Promise<void> {
  this.stopped = true;
  while (this.activeCount > 0) {
    await new Promise(r => setTimeout(r, 50));
  }
  // Slots are released in moveChunkWithSlot's finally block
}
```

(Slot đã được release trong `finally` của `moveChunkWithSlot`, nên không cần thêm logic ở đây.)
